# Knotrel v0.4.0 Release Notes — Observability & Performance

**Release candidate:** v0.4.0 is not yet published. Versions are 0.4.0 and M6
was accepted on 2026-11-15. The RC commit, its CI and release dry run, the
regression qualification of the RC against v0.3.0 (roadmap 0.4.2.3), the
repeated deployment check and maintainer release approval remain
outstanding.

## Scope

v0.4.0 completes integration-aware observability (roadmap M6) and ships the
hot-path optimizations that passed review and before/after measurement
(Feature 0.4.1). Client-visible HTTP contracts are unchanged: routes, status
codes, bodies, headers, error messages and batch semantics are the same as in
v0.3.0. Local persistence moves to v0.5.0; node/edge lifecycle (M10) and a
concurrency redesign (M5) are not part of this release.

## Observability

- **Prometheus metrics (M6.2, opt-in).** `KNOTREL_METRICS_ENABLED=true` serves
  `GET /metrics`: HTTP requests and server-side duration, pre-execution
  rejections by reason, uncertain outcomes by cause, graph-job backlog and
  capacity, queue/lock-wait/execution time per job kind, graph operations and
  feeder events by outcome, feeder rejections by code, desynchronizations by
  cause, graph node and edge counts, readiness state, worker failure, feeder
  lease remaining and last-applied age, import progress, results and phase
  durations, and catch-up duration. Every label is a compile-time enumeration;
  the series count is bounded (at most 1,414 standalone and 1,834
  source-managed) and independent of graph size, requests, generations and
  sessions. Disabled by default; with metrics disabled no accounting work is
  added. See the [observability contract](../observability-contract.md).
- **Structured logs (M6.3).** Every request runs in a `request` span with a
  process-unique `request_id`, the route and, when known, `generation`,
  `state_version` and `sync_status`. Blocking workers log inside the
  submitting request's span. New lines report synchronization transitions,
  import publication, feeder rejections by code and lease expiry; a dropped
  request logs `request cancelled before response`. Graph payloads, feeder
  session IDs and error messages quoting caller input are never logged;
  caller-supplied identifiers are escaped and truncated. `LOG_FORMAT=json`
  selects JSON lines ([contract section 17](../observability-contract.md#17-m63-structured-logs-implemented-unreleased)).
- **Alert rules (M6.4).** [`examples/observability/prometheus-alerts.yml`](../../examples/observability/prometheus-alerts.yml)
  with ten rules (worker failure, saturation, busy rejections, 5xx ratio,
  feeder loss, desynchronization, declared gaps, slow bootstrap, readiness
  flapping, repeated feeder rejections) and a [runbook](../alerting.md).
- **Qualification (M6.5).** Under a budget approved before measurement
  (paired median ≤ 3%, 95% interval upper bound ≤ 6%), enabling metrics passed
  in all six in-process router scenarios; the largest cost was +1.28%
  [+0.60%, +1.59%] on a batch of 1,024 queries
  ([campaign](../../../knotrel-benchmarks/results/metrics-overhead-20261115/README.md)). The series count stays
  constant under sustained churn of sessions, generations and node IDs
  ([contract section 18](../observability-contract.md#18-m65-qualification-overhead-and-series-count)).

## Performance

The [hot-path audit](../hot-path-audit-v0.3.0.md) reduces allocations, copies,
lookups and lock work on request, import and feeder paths without changing
results. Measured against v0.3.0-era baseline `e1e1181` with a same-binary
A/A arm on one Apple M3 host ([campaign](../../../knotrel-benchmarks/results/hot-path-audit-20261114/README.md)):

- allocations per request fall 16.7% (single query) to 75.0% (100,000-node
  import);
- in-process router: import −21%, feeder batch of 1,024 events −14% to −19%,
  batches of 1,024 queries or cut/link −6% to −9% (confirmed, metrics off and
  on); single-request latency is unchanged within noise;
- core bulk initialization: `compact-bfs` −6% to −7%, `ett-scan` and `hdt`
  sustained-churn −4% (confirmed); chain initialization on `ett-scan`/`hdt`
  inconclusive;
- end-to-end peak RSS during import −4.7% (marginal); other end-to-end
  timings inconclusive.

One marginal regression flagged by the campaign did not reproduce in a
pre-specified re-measurement ([re-check](../../../knotrel-benchmarks/results/hot-path-recheck-20261115/README.md)).
All results are joint effects of the change set; they are not attributed to
individual changes and do not transfer to other hosts without
re-measurement.

## Distribution and platform coverage

Both crates and release archives use the [Elastic License 2.0](../../LICENSE.md).
The server and development toolchain use Rust 1.100.0; `knotrel-core` retains
its Rust 1.98.1 minimum supported version. Release targets are unchanged from
v0.3.0 (Linux x86_64, macOS Apple Silicon, Windows x86_64). Measurements were
taken on one Apple M3 host and do not transfer to other hosts without
re-measurement.

## Operational and release limitations

- There is no authentication, authorization or TLS. `/metrics` is
  unauthenticated and served on the same listener: keep it inside the trust
  boundary.
- There is no durable graph persistence (planned evaluation: v0.5.0).
- No source-relative lag metric exists; `feeder_last_applied_age_seconds`
  measures inactivity, not lag.
- Alert thresholds are starting points, not service-level objectives. The
  rules file is checked against the exported series in the test suite but is
  not validated with `promtool` in CI.
- Log fields are an operational interface, stable within a minor release, not
  a machine contract.
