# v1.0.0: waiver of the `__TEXT,__text` identity rule

**Status:** maintainer decision of 2026-11-24, limited to the step from the
qualified candidate `0c49b2a` (version `1.0.0-rc.1`) to the v1.0.0 release
commit. It does not apply to any other release or change.

## The rule and why it does not hold

The [qualification plan](v1.0.0-qualification-plan.md#2-builds)
lets the release commit differ from the measured candidate only in the
version fields, and even then requires the `__TEXT,__text` section of the
`knotrel-server` release build to be identical; otherwise the affected
experiments are repeated. The maintainer decided to release 1.0.0 directly,
without publishing a release candidate. Changing only the version from
`1.0.0-rc.1` to `1.0.0` changes `__TEXT,__text`, so the rule fails.

Release builds on the same Mac (aarch64-apple-darwin, Rust 1.100.0,
`cargo build --release --locked -p knotrel-server`), compared with
`scripts/compare-binaries.py`:

| Build | Version | `__TEXT,__text` against `0c49b2a` |
|---|---|---|
| `main` at `0826888` (control: code identical to the candidate) | `1.0.0-rc.1` | identical |
| Release commit (version change only) | `1.0.0` | different: same size (2,384,192 bytes), 45,427 of 596,048 instructions differ |

The version string enters the crate metadata hashes, which appear in the
mangled symbol names; with them the layout and folding of functions change,
and with the layout the addresses and call targets in the code. After
normalizing addresses, immediates and symbol hashes, the remaining
differences are call targets and reordered functions. This is an
explanation, not a proof of identity: **binary identity is not claimed**.

## What was verified instead

Against the candidate `0c49b2a689ef548f53581c487edecd2ecc63b2df`:

- **Code:** under `crates/`, `Cargo.toml`, `Cargo.lock` and
  `rust-toolchain.toml` the delta is exactly four lines: the workspace
  version, the `knotrel-core` dependency requirement (`=1.0.0-rc.1` →
  `1.0.0`, the stable form required by `scripts/check-core-pin.py`) and the two
  `Cargo.lock` version lines of `knotrel-core` and `knotrel-server`. No source
  file changed.
- **Resolved dependencies:** the resolved graph from `cargo metadata --locked`
  (137 packages: name, version, source, enabled features and dependency edges)
  is identical apart from the two knotrel versions; `Cargo.lock` is identical
  apart from the same two lines.
- **Build configuration:** no change to profiles, `rust-toolchain.toml` or any
  Cargo configuration file; same `rustc -Vv`; no `RUSTFLAGS`.
- **Everything else in the delta** is version metadata (console
  `package.json`, OpenAPI `info.version` and the console's recorded OpenAPI
  digest, the reference feeder's version), documentation, release tooling and
  tests.

The binaries, the comparison reports, the normalized disassembly, the resolved
graphs and the code diff are kept with the evidence
(`evidence/v1.0.0-text-identity-waiver/`, private, with `SHA256SUMS`).

## Decision

- The waiver covers only the identity of `__TEXT,__text` for this version
  change. The campaign is not repeated.
- The qualification of the candidate is transferred to 1.0.0 unchanged:
  "accepted with exceptions", with every verdict, classification, disposition,
  exception and limitation of the
  [decision record](https://github.com/knotrel/knotrel-benchmarks/blob/main/results/v1.0.0-qualification/DECISION.md).
- No new measurement of the stable release is claimed: every number is the
  measurement of `0c49b2a` (version `1.0.0-rc.1`).
- The release stops if the remaining checks fail or show a substantive change.
