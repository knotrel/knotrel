# v1.0.0 qualification campaign: plan (roadmap R1)

**Status: PROPOSED (2026-11-22). Not approved. Nothing has been measured.**
The perimeter, the thresholds, the budget and the rc consequences below need
the maintainer's approval ([§15](#15-to-approve)). The candidate commit is
**not frozen**: it is frozen only after the R3 changes to release code
(including any from the R3e review) have landed
([rc plan §2](v1.0.0-rc-plan.md#2-r1--v10-qualification-campaign-and-dispositions-decided)).

not change. The detailed protocol is frozen in knotrel-benchmarks before
collection, as for v0.9.0. A failed cell is reported as failed and is not

## 1. Why and what

The maintainer decided (rc plan §2, §6.1–6.2):
- v1.0.0 gets its **own campaign** against the **latest published 0.9.x,
  frozen as the reference**, **even if the measured code is unchanged**.
- It **reuses the v0.9.0 protocol** (the v0.7.0 qualification-3 method) and
  limits the perimeter to the **relevant comparisons**, without reopening
  every diagnostic.
- Results and intervals are **published on the benchmark site**.
- The v0.9.0 exceptions are **historical evidence for v0.9.0 only**. v1.0
  dispositions are decided on the new results, with **no acceptance in
  advance**.

Release code changed since v0.9.0 ([§3](#3-release-code-changed-since-the-reference)):
the D1 fix (feeder delivery sequence 0), `busy` for exhausted feeder lanes,
`too_many_connections` in the error enum, input byte limits on feeder
positions and event IDs, per-lane admission metrics, `#[non_exhaustive]` on
five public types, and the `router_with_lifecycle` documentation. More may
come from R3e. [§3](#3-release-code-changed-since-the-reference) is
recomputed on the frozen candidate before the protocol is frozen.

### 4.3 The core rule

Decided **at the freeze, from builds, never from measurements**: compare
`__TEXT,__text` of the release builds of the core probes (`core`,
`core-count`, `core-lifecycle`) and of the A core harness, built against the
candidate and against the reference. The binaries must be identical apart
from the knotrel-core version.
- **Identical:** the core's executed code did not change. The perimeter is
  as in §4.1. The A core cells, E4–E5 and C still run (rc plan §2: measured
  even if unchanged).
- **Different:** B1–B3, B5, T5 and Rmem join the perimeter with their
  frozen cells and thresholds (the full BC collector in place of
  `--only B4,C`). The budget grows as [§9](#9-budget-and-duration) states.

The comparison and its outcome are recorded in the freeze record.

## 5. Method

The v0.7.0 qualification-3 method as re-run in v0.9.0 (`MATRIX
references.method`; `PROTOCOL §2`), unchanged except for the binaries, the
campaign directory, the bindings and the perimeter.

### 5.1 Common rules

- **Interval** (`MATRIX rules.interval`): paired log ratios `ln(C/B)`; the
  distribution-free interval of the median from one-based order statistics:
  n = 12 → `[r(3), r(10)]`; n = 24 → `[r(7), r(18)]`. Coverage under a
  continuous symmetric model: 96.1 % and 97.7 % (binomial, p = ½).
- **Classification** (`MATRIX rules.classification`): PASS if upper ≤
  ln(1+t); REGRESSION if lower > ln(1+t); otherwise INCONCLUSIVE. For
  higher-is-better metrics the ratio is B/C. IMPROVED is reported only when
  the upper bound is below 0, and nothing more is claimed from it.
- **Timer limit** (`analyze_lifecycle_qualification.py`): a B cell whose
  median window in either arm is below 1 ms is TIMER_LIMITED. Its numbers are
  kept and it gets no verdict.
- **No inheritance:** no v0.9.0 or earlier waiver, acceptance or result is
  reused, pooled or used to choose cells (`MATRIX rules.no_waiver_inheritance`,
  extended to v0.9.0).

### 5.3 Validity, interference and conformance

- **Validity** (`MATRIX rules.validity`): a configuration record is VALID
  only if `errors == 0`, `item_errors` is empty, `noop_mutations == 0` and,
  with background activity, `background.failures == 0` and
  `background.completed > 0`. 503 refusals are allowed and reported. Every
  analyzed M_reg observation must have only status 200. An invalid record is
  reported, never rerun or dropped. An M_reg cell with any invalid analyzed
  observation gets **INVALID** (no verdict).
- **Atomicity** (`MATRIX experiments.B_C.equivalent_references.atomicity_rule`):
  a deciding equivalent cell whose records show `atomicity_equivalent` false
  is reported **NOT_EQUIVALENT**, among the deciding non-PASS results.
- **Host** (`MATRIX host_conditions`): AC power and no thermal or
  performance warning, checked before every child; `caffeinate -dimsu`;
  nothing else heavy running (no builds, no other benchmark).
- **Interference policy:** revision 3, proportional (`MATRIX
  conformance.qualification_3.revision_3`). Measured indicators: external
  CPU, memory pressure, system sleep, AC power, thermal warning and telemetry
  coverage. Limits: `invalid_window_s` 10, `invalid_cpu` 1.5,
  `ready_window_s` 30, `ready_cpu` 0.6, `pressure_max` 1, `sleep_jump_s` 2,
  `wait_limit_s` 600, `retries` 2, `min_free_bytes` 3 GiB. User input,
  busiest processes, swap and load average are context only. Units:
  A block (at most one restart, `limits.a_block_restarts`), B/C cell, R pair,
  M_reg pair.
- **Conformance outcome** (`MATRIX conformance.outcome`): any failed check
  stops the chain at the next gate and makes the whole attempt
  **NONCONFORMING**. No experiment of that attempt gets a verdict, completed
  ones included. Data are kept. Every exit path writes
  `logs/CONFORMANCE.txt`, the final Git state and checksums.
- **Q** has no chain gate (as in v0.9.0). It runs only after Part 1 ends
  CONFORMING. Host problems are handled by the protocol's repetition rule and
  recorded.

### 5.4 Attempts, invalidation and reruns

- **Attempts** (`MATRIX conformance.qualification_3.attempts_rule`, applied
  to a new series `v100q`): **one** attempt, **cap 2**. A second attempt only
  if the first does not conform (gate, budget or recovery exhausted), never
  because of a result. The first CONFORMING attempt is final. Every
  directory counts. A second non-conforming attempt ends the campaign for a
  maintainer decision.
- **Code change** (`MATRIX invalidation.code_change`): any change to executed
  knotrel code after the freeze invalidates every experiment that ran that
  code. Documentation-only commits do not. Executed-code identity is checked
  by comparing `__TEXT,__text` of release builds.
- **Tooling change** (`MATRIX invalidation.tooling_change`): any change to a
  probe, collector or analyzer after the freeze invalidates the affected
  experiment.
- **Failed child** (`MATRIX invalidation.failed_child`): a failing child
  stops the experiment. **One** rerun only, for an infrastructure failure
  unrelated to the measured code, recorded with its cause. Conformance
  failures are not infrastructure failures and do not use this allowance.
- **Invalid runs** are kept and reported, never deleted or overwritten.

## 7. Classification and outcomes

| Outcome | Applies to | Meaning | Treatment |
| --- | --- | --- | --- |
| **PASS** | Deciding cells, criteria | Upper bound within tolerance; criterion met | None |
| **REGRESSION** | A, B4, R, M_reg | Lower bound beyond tolerance | Non-PASS, needs a maintainer disposition |
| **FAIL** | B5, C1–C3, Q1–Q5 | Rule not met | Non-PASS, needs a disposition |
| **INCONCLUSIVE** | A, B4, R, M_reg | Interval crosses the tolerance | Non-PASS, needs a disposition |
| **INCONCLUSIVE_DISCLOSED** | A only | INCONCLUSIVE primary, median ≤ t, every supporting metric PASS | Non-PASS, disclosed, needs a disposition |
| **UNRESOLVED** | A only | Any other A cell with a non-PASS gated metric, including an INCONCLUSIVE supporting metric | Non-PASS, needs a disposition |
| **NOT_EQUIVALENT** | Deciding B4 equivalent cells | Records show `atomicity_equivalent` false | Non-PASS, needs a disposition |
| **TIMER_LIMITED** | B cells | Median window < 1 ms in an arm | No verdict, numbers kept, listed |
| **Disclosure categories** | C4 (EXCEEDS_BUDGET); descriptive B4 frozen cells (including the `import-high` REGRESSION) | Reported by rule, not a deciding result | Published with their numbers. Not deciding, not converted. They do not need a disposition but are named in the release notes. |
| **No verdict** | E6 (2 cells), block D | Not qualifiable by comparison / descriptive | Indicative numbers only |
| **INVALID** | M_reg cell | An analyzed observation is invalid | No verdict for the cell; non-PASS for the rc rule |
| **NONCONFORMING** | Whole attempt | A conformance check failed | No verdict for any experiment of the attempt. Second attempt as in [§5.4](#54-attempts-invalidation-and-reruns). |

The campaign is **valid** if one attempt is CONFORMING for Part 1 and Q ran
to completion under its protocol. v1.0.0 is **qualified** only if the
campaign is valid and every deciding cell and criterion is PASS. Any other
result is reported as it is, for a maintainer decision. No rule changes
after collection. No rerun is chosen by its result.

## 8. Consequences for the rc (proposed)

The rc plan has no separate blocking rule. It makes the rc depend on R1
(§1) and requires one maintainer decision per non-PASS result (§2). Proposed
rule:

1. **Blocking:** `v1.0.0-rc.1` is not tagged until the campaign is valid
   and **every non-PASS result** (REGRESSION, FAIL, INCONCLUSIVE,
   INCONCLUSIVE_DISCLOSED, UNRESOLVED, NOT_EQUIVALENT, INVALID, Q3 if FAIL)
   and E6 have a **recorded maintainer disposition**:
   - **accepted for v1.0**, with the classification kept and disclosed;
   - **assigned to v1.2.0 H2** with a criterion; or
   - **fixed and re-measured.**
2. **A fix changes the candidate.** Every experiment that executed the
   changed code (`__TEXT,__text` rule) is repeated on the new candidate
   under the same frozen method, as a recorded freeze revision. The earlier
   results stay published as superseded, never deleted. Experiments whose
   executed code is unchanged keep their results.
3. **Classifications, intervals and thresholds stay as measured** in every
   case. A disposition is recorded next to the verdict, never in place of
   it.
4. **NONCONFORMING twice:** no rc until the maintainer decides how to
   proceed.
5. **Release commit:** the rc and 1.0 commits satisfy the release commit
   rule ([§2](#2-builds)), or the affected experiments are repeated before
   the tag.
6. **Disclosure categories and TIMER_LIMITED cells** do not block. They are
   listed in the release notes.
