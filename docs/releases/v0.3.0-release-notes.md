# Knotrel v0.3.0 Release Notes

**Release candidate:** v0.3.0 is not yet published. Final RC checks and
maintainer release approval remain outstanding.

## Reduced release scope

- The compatible standalone batch contract executes operations in order,
  returns one outcome per operation, and continues after domain errors.
  Successful mutations remain applied in memory; the batch is not a
  transaction. Queries observe earlier successful operations and effective
  mutations advance the revision.
- The feeder failure model and retry/reconciliation guidance distinguish the
  source-managed applied-prefix protocol from standalone batch behavior.
  Existing failure, duplicate, concurrency and rebuild tests support those
  contracts.
- Lifecycle guidance covers liveness, synchronized readiness, draining and
  startup-only configuration. The [container and external-feeder example](../deployment.md)
  includes startup, lease expiry, restart and authoritative rebuild.

The full M3.6 throughput, fairness and queue-depth evaluation; M5 contention
instrumentation and concurrency redesign; M6 Prometheus/alerting expansion and
its overhead qualification; P2; the full original P3 matrix; and quantitative
source-relative lag reporting are deferred. The existing coarse graph mutex is
retained. No persistence, new concurrency mechanism or optimization is added by
this release plan. The already-merged Candidate A remains in the candidate
without an attributed performance benefit.

## Performance qualification

The approved nine-cell comparison used a Rust 1.100.0 rebuild of v0.2.0 and
candidate `6a1267f48c0f72f5b9705ad7f44da74af54b9b70`, with the same harness
source and one shared HTTP driver. The initial campaign recorded 108 pairs; the single permitted
extension added 36 pairs for the three initially inconclusive cells. All 288
observations were valid. Results are limited to the specified workloads and
`compact-bfs`/`compact-workspace` on the macOS arm64 measurement host.

The table gives the median paired change `exp(median(ln(C/B))) - 1` and the
approved order-statistic interval. PASS is a decision under the approved
tolerance, not a significance test or proof that regressions are absent.

| Cell | Pairs | Median paired change | Interval | Outcome |
|---|---:|---:|---:|---|
| Core sparse traversal, compact-bfs | 12 | +0.10% | -21.95% to +6.14% | PASS |
| Core sparse traversal, compact-workspace | 24 | -2.26% | -11.13% to +9.41% | PASS |
| Core sustained churn, compact-bfs | 12 | -0.01% | -1.76% to +8.01% | PASS |
| Core sustained churn, compact-workspace | 12 | -0.46% | -5.30% to +0.76% | PASS |
| HTTP batch B1 | 12 | -0.71% | -7.37% to +7.69% | PASS |
| HTTP batch B8 | 24 | **-1.42%** | **-15.63% to +12.09%** | **INCONCLUSIVE** |
| HTTP batch B64 | 12 | -0.83% | -7.56% to +5.08% | PASS |
| HTTP batch B256 | 12 | +0.08% | -1.55% to +6.98% | PASS |
| HTTP lifecycle readiness | 24 | **+8.02%** | **-11.46% to +21.97%** | **INCONCLUSIVE** |

There are **7 PASS and 2 INCONCLUSIVE** outcomes. The two inconclusive cells are
accepted for release with this disclosure under the previously approved D6
policy; they are not PASS results and their intervals do not exclude
regressions. Correctness and identity checks reported no failures, and the
p99/RSS guardrails did not trigger under the approved rule. No performance
improvement is claimed. Final applicability to the RC is subject to the
[dependency-aware qualification check](../release-v0.3.0-closure-plan.md#59-invalidation).

## Operational and release limitations

- There is no authentication, authorization or TLS. Restrict access to trusted
  clients and networks; anyone with access can mutate the graph or take over
  the feeder session.
- There is no durable graph persistence. Restart loses graph and synchronization
  state; the authoritative source must provide a complete snapshot for rebuild
  and retain unacknowledged events.
- `catching_up` and `stale` are synchronization states, not measurements of
  source-relative lag. Readiness after a feeder exit lasts only while its lease
  remains current; the reference feeder stops heartbeating when it exits.
- A single feeder session owns the graph, with fenced takeover rather than
  load balancing. The deduplication window is bounded. Normal eviction needs
  no rebuild, but an uncertain retry reported as `unverifiable_duplicate`
  requires reconciliation by replacement import, not a blind skip or resend.
- The feeder and container are examples, not a supported production connector
  or published image. Configuration is read at startup.
- There is no Prometheus endpoint or new alerting/overhead qualification.
- If crates.io confirms `knotrel-core` 0.3.0 is absent, the server publish dry
  run is deferred until the core is published. Offline package verification
  and a successful release-workflow dry run do not guarantee publication.
