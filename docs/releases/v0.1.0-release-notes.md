# Knotrel v0.1.0 Release Notes (Public Preview)

Knotrel v0.1.0 is the first public preview release of Knotrel, a specialized dynamic connectivity engine for undirected graphs.

## What is Knotrel?

Knotrel answers one question quickly and accurately: **Are two vertices connected in an evolving undirected graph?**

It provides:
1. **`knotrel-core`**: A synchronous Rust library providing exact dynamic connectivity algorithms (`link`, `cut`, `connected`) with zero unsafe code.
2. **`knotrel-server`**: A lightweight HTTP service built with Axum, exposing dynamic connectivity operations over a JSON API.

## Quick Start with Prebuilt Binary

### 1. Download and verify checksum

Download the archive and corresponding `.sha256` checksum file from GitHub Releases:

```sh
# Verify SHA-256 checksum on Linux:
sha256sum -c knotrel-server-v0.1.0-x86_64-unknown-linux-gnu.tar.gz.sha256

# Or on macOS using shasum:
shasum -a 256 -c knotrel-server-v0.1.0-aarch64-apple-darwin.tar.gz.sha256
```

### 2. Extract and run

#### Linux (x86_64):
```sh
tar -xzf knotrel-server-v0.1.0-x86_64-unknown-linux-gnu.tar.gz
cd knotrel-server-v0.1.0-x86_64-unknown-linux-gnu
./knotrel-server
```

#### macOS (Apple Silicon):
```sh
tar -xzf knotrel-server-v0.1.0-aarch64-apple-darwin.tar.gz
cd knotrel-server-v0.1.0-aarch64-apple-darwin
./knotrel-server
```

#### Windows (x86_64):
```powershell
Expand-Archive knotrel-server-v0.1.0-x86_64-pc-windows-msvc.zip
cd knotrel-server-v0.1.0-x86_64-pc-windows-msvc
.\knotrel-server.exe
```

By default, the server binds to `127.0.0.1:8080` on loopback.

### 3. Send requests

```sh
# Health and readiness
curl -sS http://127.0.0.1:8080/health
curl -sS http://127.0.0.1:8080/ready

# Link vertices 1 and 2
curl -sS -H "Content-Type: application/json" \
  -d '{"op":"link","source":"1","target":"2"}' \
  http://127.0.0.1:8080/v1/operations

# Query connectivity
curl -sS -H "Content-Type: application/json" \
  -d '{"op":"connected","source":"1","target":"2"}' \
  http://127.0.0.1:8080/v1/operations
# => {"result":"connected","connected":true}
```

## Engine Implementations

Knotrel provides three dynamic connectivity engines:
1. **Compact BFS (`compact-bfs`, default)**: Cache-friendly sorted adjacency vectors with fast traversal. Simple, robust, low-memory default for general and mutation-heavy workloads.
2. **Euler Tour Trees (`ett`, experimental)**: Single spanning forest using AVL-balanced Euler tour sequences with candidate pruning. Optimized for query-dominated tree workloads.
3. **Holm–de Lichtenberg–Thorup (`hdt`, experimental)**: Level-based deterministic dynamic graph algorithm bounding amortized updates to $O(\log^2 V)$. Avoids edge scan storms on dense graphs undergoing bridge cuts.
   *Implementation assumptions*: Bounds apply to internal index structures under an append-only vertex universe model. External node ID lookups rely on expected $O(1)$ hash map lookups. Stated update bounds represent amortized sequence averages rather than worst-case per-request latency bounds.

## Key Boundaries and Limitations

> [!WARNING]
> **Ephemeral in-memory state**: Knotrel v0.1.0 has **no persistence, write-ahead logging, or crash recovery**. Stopping or killing the process loses the entire graph. Durability, snapshotting, and recovery are planned for v0.2.0.

> [!CAUTION]
> **Security boundary**: Knotrel v0.1.0 contains **no authentication, authorization, rate limiting, or TLS encryption**. The server defaults to `127.0.0.1:8080` (loopback only) and rejects non-loopback addresses unless explicitly overridden with `KNOTREL_ALLOW_NON_LOOPBACK=true`. It is intended strictly for localhost or trusted, access-controlled internal networks.

> [!NOTE]
> **Not a general-purpose graph database**: Knotrel maintains exact 0-1 connectivity between undirected nodes. It does not store edge weights, directional graphs, arbitrary vertex attributes, property graphs, or Cypher/SPARQL queries.

## Lifecycle, Health, and Exit Codes

- **Liveness (`/health`)**: Returns `200 OK` while the process is alive.
- **Readiness (`/ready`)**: Returns `200 OK` when ready to accept queries/mutations; returns `503 Service Unavailable` during startup, drain, or worker fault.
- **Shutdown & Drain**:
  - On Unix (Linux / macOS), graceful shutdown is initiated by `SIGINT` or `SIGTERM`.
  - On Windows, Unix signals are not supported; shutdown is initiated by `Ctrl+C` or platform process termination.
  - When shutdown begins, the server transitions to `draining`, stops accepting new connections, and drains admitted requests up to `KNOTREL_SHUTDOWN_TIMEOUT_MS` (default 10s).
- **Process Exit Status Codes**:
  - `0`: Normal clean exit; all admitted connections and graph workers drained before the timeout.
  - `2`: Shutdown deadline exceeded; active connections or worker jobs remained when `KNOTREL_SHUTDOWN_TIMEOUT_MS` expired.
  - `130`: Forced immediate termination; a second signal was received while draining.
