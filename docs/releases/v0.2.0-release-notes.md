# Knotrel v0.2.0 Release Notes (Integration & Graph Loading)

Knotrel v0.2.0 introduces the **External Source-of-Truth Integration Model**, enabling Knotrel to operate as an in-memory dynamic connectivity accelerator fed continuously by an authoritative external store or event stream.

---

## Highlights

- **External Source-of-Truth Integration Contract**: Formal lifecycle state machine supporting `SourceManaged` mode alongside existing `Standalone` mode. External systems retain absolute authority; Knotrel accelerates exact connectivity queries.
- **Bounded Atomic HTTP Graph Import**: Fast, atomic replacement via `POST /v1/feeder/import`. Candidate graph structures are constructed off-lock without blocking concurrent read traffic, with body limits, cardinality caps, and strict precondition verification.
- **Graph Identity & Coherent Versioning**: Coherent version tuples combining server instance ID, generation number, arbitrary-precision local revision counters, and canonical 256-byte source cursor positions exposed via HTTP response headers and ETags.
- **Ordered Incremental Events & Deduplication**: High-performance streaming update endpoint `POST /v1/feeder/events` with sequence monotonicity, strict predecessor verification, gap rejection, and sliding-window event deduplication.
- **Synchronization-Aware Readiness Probes**: `/ready` actively checks feeder heartbeat lease validity and sync states (`uninitialized`, `loading`, `catching_up`, `ready`, `stale`, `desynchronized`) using lock-free published readiness packing.
- **Deterministic Import Reconciliation & E2E Verification**: 21 comprehensive end-to-end rebuild and fault-recovery tests covering network partition, lost acknowledgments, competing feeder takeovers, and race-free reconciliation.

## What's New in v0.2.0

### 1. Integration Mode & Feeder Sessions
Knotrel can run in `Standalone` mode (the default from v0.1.0) or `SourceManaged` mode (configured via `KNOTREL_MODE=source-managed`).
In `SourceManaged` mode:
- Direct ad-hoc mutations to `/v1/operations` and `/v1/batch` are rejected with HTTP 403 / 409 to prevent desynchronization with the authoritative store.
- Authorized external feeders establish an ownership session via `POST /v1/feeder/session` and maintain active heartbeats with lease renewal via `POST /v1/feeder/heartbeat`.

### 2. Atomic Snapshot Import (`/v1/feeder/import`)
- Imports a complete snapshot of graph connectivity with cursor attribution.
- Candidate graph construction occurs off-lock. The active graph lock is held only during the final pointer swap and metadata publication, keeping query latency bounded.
- Rejection of oversized bodies (`MAX_BODY_BYTES`), malformed shapes, or invalid node IDs without state corruption.
- Safe reconciliation protocol for feeder recovery after lost acknowledgments without relying on non-proving count equalities.

### 3. Ordered Event Stream (`/v1/feeder/events`)
- Incremental graph changes (`link` and `cut`) are delivered with sequence numbers and predecessor cursors.
- Out-of-order deliveries and gaps are rejected with deterministic error codes, allowing the feeder to rewind or re-synchronize cleanly.
- Bounded duplicate window deduplicates at-least-once deliveries.

### 4. Readiness & Health Observability
- `/health` continues to report process liveness.
- `/ready` in `SourceManaged` mode reports HTTP 200 only when the graph is fully synchronized (`status: "ready"`) and the feeder lease is active.
- If a feeder heartbeat expires, `/ready` transitions to HTTP 503 (`status: "stale"`), signaling traffic balancers to divert queries away until re-synchronized.

## Quick Start (Integration Feeder Example)

```sh
# 1. Start knotrel-server in source-managed mode
export KNOTREL_MODE=source-managed
export KNOTREL_FEEDER_LEASE_MS=10000
./knotrel-server

# 2. Acquire feeder session
curl -sS -X POST http://127.0.0.1:8080/v1/feeder/session \
  -H "Content-Type: application/json" \
  -d '{"feeder_id":"feeder-prod-1","lease_duration_ms":10000}'

# 3. Publish initial snapshot
curl -sS -X POST http://127.0.0.1:8080/v1/feeder/import \
  -H "Content-Type: application/json" \
  -H "X-Knotrel-Feeder-ID: feeder-prod-1" \
  -H "X-Knotrel-Generation-Precondition: 0" \
  -d '{
    "cursor": "cursor-001",
    "nodes": ["1", "2", "3"],
    "edges": [["1", "2"], ["2", "3"]]
  }'

# 4. Stream ordered updates
curl -sS -X POST http://127.0.0.1:8080/v1/feeder/events \
  -H "Content-Type: application/json" \
  -H "X-Knotrel-Feeder-ID: feeder-prod-1" \
  -d '{
    "events": [
      {
        "event_id": "evt-1",
        "sequence": 1,
        "predecessor_cursor": "cursor-001",
        "cursor": "cursor-002",
        "op": "link",
        "source": "1",
        "target": "3"
      }
    ]
  }'

# 5. Query connectivity
curl -sS -X POST http://127.0.0.1:8080/v1/operations \
  -H "Content-Type: application/json" \
  -d '{"op":"connected","source":"1","target":"3"}'
# => {"result":"connected","connected":true}
```

## Backward Compatibility

- **Standalone Mode Unchanged**: Knotrel retains full backward compatibility with v0.1.0 for standalone usage, embedded library usage (`knotrel-core`), and standard query APIs.
- **Engine Selection**: `compact-bfs` (default), `ett`, and `hdt` remain available with identical exact connectivity semantics.

---

## Security Boundary & Operational Recommendations

- Knotrel v0.2.0 remains an in-memory accelerator intended to run in a trusted, access-controlled environment or on localhost (`127.0.0.1:8080`).
- Knotrel does not provide TLS or RBAC internally; production deployments should terminate TLS and enforce network isolation via reverse proxies or service meshes.
