## 1. Scope and method

**Scope:** the public contract that v1.0.0 is about to freeze, and the changes
`v0.9.0..e1be11c` (84 files) that produced it:

- the Rust public API of `knotrel-core` and `knotrel-server`: docs, error
  contracts, `#[non_exhaustive]`, stability classes, constructors, panics
  reachable from public input;
- the HTTP API: `docs/openapi.yaml` and `docs/http-api.md` against the router
  and the handlers (routes, fields, statuses, error codes, limits counted in
  bytes, version headers, readiness and drain);
- the `KNOTREL_*` configuration; the metrics and alerts, including the
  per-lane semantics; the feeder protocol (`docs/integration-contract.md`)
  against the code and the tests, including the traceability in
  [criterion 3 evidence](v1.0-criterion-3-evidence.md);
- the compatibility and stability policy (`docs/compatibility.md`,
  `docs/stability.md`, `docs/api/*`), including "stable interface,
  experimental engine" for ETT and HDT and the `storage_stats` guarantees;
- the public API checker (`scripts/public-api.py`, `tests/test_public_api.py`,
  the `public API` CI job), and the HTTP compatibility checker that enforces
  the same policy for OpenAPI (`scripts/check-openapi-compat.py`);
- the threat model's coverage of the contract.

The yardstick is the [freeze review](v1.0-contract-freeze-review.md): its
frozen list (section 5) as amended by the maintainer's decisions in sections
7 and 7.1.

**Method:** documents and code were read directly. PR descriptions, the
freeze review's own findings and the sibling sessions' notes were not used as
evidence. Claims were checked with these commands:

| Command | Result |
| --- | --- |
| `cargo test --workspace --all-features --locked` | pass: 614 passed, 0 failed, 1 ignored, across 35 test binaries plus doctests |
| `python3 tests/test_public_api.py` | pass: 50 tests |
| `python3 scripts/public-api.py check --base v0.9.0` | pass: "snapshot, classification, policy and stability.md agree (615 classified keys)", with "note: the base has no classification file; narrowing check against the base skipped" (see N1) |
| `python3 scripts/check-openapi-compat.py v0.9.0:docs/openapi.yaml docs/openapi.yaml --approved docs/api/approved-breaking-changes.yaml` | pass: "10 approved breaking change(s), 0 note(s)" |
| Mutation test of `check-openapi-compat.py`: `busy` removed from `ErrorCode` and `hdt` from `ServerInfo.engine` | "OpenAPI compatible", exit 0 (see B2) |
| Throwaway programs outside the repository (scratch crates that depend on the crates by path, with their own target directories) | Panic probes of the core API; oneshot HTTP probes of barrier, drain, inspection and validation order |

**Not reviewed:**

- performance, benchmarks and the qualification campaign: no measurement was
  run;
- the console beyond its contract coupling (error-code list,
  `supportedServer`, OpenAPI digest), and its UI;
- the PostgreSQL reference feeder (an example with no promise), the gateway
  and console container configurations (only as cited by the threat model);
- release workflows, reproducible build, SBOM and supply chain;
- `cargo semver-checks`, `cargo doc`, Clippy and `openapi-spec-validator`:
  CI runs them, and this review did not re-run them;
- the soak's statistical adequacy; only its traceability was checked;
- repository settings and branch protection: whether the `public API` and
  `API compatibility` jobs are required checks was not verified.

An AI review can miss defects, and the absence of a finding is not evidence
of correctness.
