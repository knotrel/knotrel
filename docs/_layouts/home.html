Connectivity for changing networks

Knotrel keeps an undirected graph in memory and answers exact connectivity queries as nodes and edges change. Use it as a Rust library or an HTTP service alongside your existing source of data.

Get started View on GitHub

How it works

Three operations, one exact answer

  1. 1

    Load a graph

    Build it from your edges, or let a feeder import a baseline from your authoritative source.

    try_from_edges · POST /v1/feeder/import
  2. 2

    Apply changes

    Link and cut edges as the network changes. Optional lifecycle flags take nodes and edges offline without deleting them.

    link · cut · set_node_active
  3. 3

    Ask “connected?”

    Every answer is exact and reflects all operations applied before it. No sampling, no stale cache.

    connected(source, target)

Try it

A failure and a recovery in one request

Start the server and send a batch: link a path, check it, cut an edge, check again. A batch runs under one lock, so no other request interleaves with it.

HTTP API reference →
Rust crate documentation →

# standalone mode, default address
curl -sS http://127.0.0.1:8080/v1/batch \
  -H 'Content-Type: application/json' \
  -d '{"operations":[
    {"op":"link","source":"1","target":"2"},
    {"op":"link","source":"2","target":"3"},
    {"op":"connected","source":"1","target":"3"},
    {"op":"cut","source":"2","target":"3"},
    {"op":"connected","source":"1","target":"3"}
  ]}'

# results, one per operation
… {"result":"connected","connected":true} …
… {"result":"connected","connected":false}
use knotrel_core::{ConnectivityGraph, EngineConfig};

let mut graph = ConnectivityGraph::new(EngineConfig::CompactBfs);
graph.link(1, 2)?;
graph.link(2, 3)?;
assert!(graph.connected(1, 3)?);

// Cut an edge and observe the split.
graph.cut(2, 3)?;
assert!(!graph.connected(1, 3)?);
